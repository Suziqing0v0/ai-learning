## 问题一：计算机没有骰子，`np.random.rand()` 凭什么每次给你一个不一样的数？

### 我第一次怎么答的

> 「随即给的」

**老师说**：这是把问题重复了一遍。我问的是"**凭什么**"——它凭什么能给你一个不一样的数。

### 提示之后我答的

> 「计算出来的」

**对。这就是这一题的核心。**

### 整理

- 计算机的词汇表里**根本没有"随机"这个词**，它会做的只有：加减乘除、比大小、取余、跳转
- 它从一个**起点数字**出发，用一条**固定公式**算出下一个数，再算出下一个……
- 所以它其实不随机。正式名字叫**伪随机**：`pseudo` = 假的、仿的
- 例子：`下一个数 =（上一个数 × 37 + 11）的后两位`，从 42 开始：

  ```
  42 → 65 → 16 → 3 → 22 → 25 → 36 → 43 → 2 → 85 → 56
  ```

  每一步都是纯算术，但看起来乱七八糟。（验算第一步：42 × 37 = 1554，加 11 = 1565，后两位 65）

- 这个例子里"后两位"只有 00~99 一百种可能，所以**最多算 100 个就会撞回老数**、开始原地循环。
  真的生成器用的模数大到离谱（2 的几十次方位），周期长到一辈子算不完。
  **原理一样，只是数字大得吓人。**

## 问题二：随机数既然是算出来的，"同一个 seed 得到同一串数字"为什么对做实验的人反而是好事？

### 我的原话

> 「因为实验需要能复现，不能每次不一样」

**这题一次就答对了。关键词是"复现"。**

### 整理

- 做实验最怕的是"上次那个结果再也做不出来"
- 同一个 seed = 同一个起点 = 同一串数 → 别人拿着你的代码能跑出一样的结果
- 换个 seed 就是另一串数 —— 所以"看起来随机"和"能复现"可以同时成立
- 补充：真随机数生成器连**起点**都不是你给的，是从系统噪声里抓的，所以才有"每次都不一样"的错觉。
  你给 seed，就是把它按住不让它乱跑

## 这一轮我犯的两个小错（记下来）

1. **拼写**：`随即` → `随机`
   - 随即 = 随后、立刻；随机 = random
2. **答问题的方式**：第一次答"随即给的"，其实是把问题重复了一遍。
   - 以后看到"**凭什么 / 为什么 / 怎么来的**"这种问法，答"它就是这样"不算答案

## 一句话总结

**随机数是被算出来的，种子决定从哪开始算；所以它既能看起来随机，又能被复现。**
