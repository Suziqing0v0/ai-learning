## 一之补 · 提示分级协议（第 2 周起生效）

**核心原则：不要花时间猜语法，要花时间想结构。**

**分两种情况处理：**

| 情况 | 怎么处理 |
|---|---|
| **写不出来（卡住）** | 不给答案。换成**类似场景的例子**（数据、内容不同，结构一样），你自己迁移过来 |
| **写错了（报错或结果不对）** | 直接指出错在哪 + 怎么改，不绕弯 |

**四条规则**

1. **任务本身永远不给现成代码。** 卡住时我给换一个场景的例子，比如你要算 BMI 我却举例算速度——结构一样，你自己照搬改造
2. 你贴代码说「看一下」时，**我先问**："运行结果是什么？你觉得哪里不对？"——你答不上来我才给提示
3. **出错直接给改正方法**（这一条保持原来的做法）。需要时按三级提示：
   - 一级：只指出位置（"问题在第 3 行"）
   - 二级：指出类型（"这是括号配对问题"）
   - 三级：给出那一行的写法
4. 报错先自己读三遍再问我，读报错本身就是最值钱的思考环节

**作业要求必须写清四件事**（要求模糊是我的问题，不是你的）：

1. **要做什么** —— 一句话说清任务
2. **输入/数据是什么** —— 数据从哪来、长什么样
3. **输出长什么样** —— 贴出期望的样例
4. **怎么算过关** —— 可勾选的验收标准

**新代码要逐词解释**：出现新语法或新函数时，除了用法，还要说清每个词的**英文含义**。
比如 `return` = 返回、`append` = 追加、`IndentationError` = 缩进·错误。
知道单词意思，代码就从"一堆符号"变成"能读的句子"，也更容易记住。
词典见 `代码模板.md` 第 11 节。

**你可以用的两个口令**

- 「**别给答案**」→ 我只提示，你写到卡死为止
- 「**给答案**」→ 我直接给，不绕弯

## 二之补 · 磁盘铁律：能装 D 盘的一律装 D 盘

你的 C 盘只剩约 27 GB，从今天起：**所有软件、缓存、环境、数据默认装 D 盘，只有必须装 C 盘的才例外。**

| 项目 | 位置 | 现状 |
|---|---|---|
| Python 3.12.10 | `D:\Python312` | 已装 |
| VS Code | `D:\VSCode` | 已装 |
| pip 下载缓存 | `D:\pip-cache` | 已配置 |
| Python 安装包备份 | `D:\pymsi` | 已留存（约 15 MB，重装时用） |
| 以后：HuggingFace 模型缓存 | `D:\hf-cache` | 待配置 |
| 以后：数据集、大项目 | `D:\ai-learning\` | 待建 |
| 本计划的文档 + 你的作业代码 | 当前目录（C 盘） | 几 MB |

最后一行是唯一例外：这套文档和你的作业加起来只有几 MB，留在这里是为了我能直接读文件批改。**真正撑爆 C 盘的是环境和缓存，不是文本文件。**

以后装任何新软件（PyCharm、Git、CUDA Toolkit、Docker 等）都先改安装路径到 D 盘。
等学到阶段 4 需要下载预训练模型时，记得设 `HF_HOME=D:\hf-cache`，否则 HuggingFace 会往 C 盘塞几十 G。

> **环境已经装好了，不用你再动手。** 细节和排障记录见 `环境说明.md`。

1. **把项目和课程绑在一起**。你在学量子力学，就顺手做第 7 周的势阱项目；学热统就做第 14 周的 Ising。一次投入，两份收获。
